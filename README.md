# Система учёта заявок

Учебный Python-проект по дисциплине «Технологии разработки программного обеспечения». Репозиторий содержит материалы лабораторных 1–8: требования, архитектуру, прототип, модель SQLite, приложение FastAPI, REST API и конфигурацию контейнера. ЛР № 5 отражена ER-диаграммой, SQL-схемой и отчётом.

## Возможности

- Создание, просмотр, редактирование и архивирование заявок.
- Фильтрация по статусу, категории, приоритету и текстовый поиск.
- Назначение исполнителя, смена статуса с проверкой допустимых переходов.
- Комментарии и история изменений.
- REST API FastAPI с OpenAPI/Swagger.
- HTML-интерфейс, подключённый к API.
- Инициализация SQLite и идемпотентные демонстрационные данные: 4 пользователя, 4 категории, 4 статуса и 10 заявок.

> Это учебный демонстрационный продукт без аутентификации и авторизации. Не разворачивайте его публично с реальными пользовательскими данными до добавления защиты доступа.

## Локальный запуск без Docker

Требуется Python 3.12+.

```powershell
py -3.12 -m venv .venv
 .\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
$env:DATABASE_URL = "sqlite:///./data/requests.db"
python -m uvicorn app.main:app --reload
```

Откройте интерфейс на <http://127.0.0.1:8000/>, Swagger UI на <http://127.0.0.1:8000/docs>, OpenAPI JSON на <http://127.0.0.1:8000/openapi.json>, проверку состояния на <http://127.0.0.1:8000/health>.

Первый запуск создаёт таблицы и тестовые записи. Повторный запуск не дублирует сиды. Для ручного повторного наполнения пустых таблиц выполните `python -m scripts.seed`.

### Настройки

Скопируйте `.env.example` в `.env` и задайте значения локально. `.env` игнорируется Git. Переменные: `APP_ENV`, `HOST`, `PORT`, `DATABASE_URL`. Не помещайте секреты в `.env.example` или коммиты.

## REST API

Подробная таблица методов находится в [`docs/API.md`](docs/API.md). Примеры запросов: [`docs/requests.http`](docs/requests.http); Postman-коллекция: [`docs/postman_collection.json`](docs/postman_collection.json).

Базовые запросы:

```http
GET /requests?q=монитор&status_id=1
POST /requests
Content-Type: application/json

{"title":"Не работает принтер","description":"Принтер не печатает документы.","category_id":1,"requester_id":1,"priority":"high"}
```

Успешное создание возвращает `201`; несуществующая запись — `404`; невалидная схема или недопустимый переход статуса — `422`; удаление выполняет мягкую архивацию и возвращает `204`.

## Автоматические тесты

Установите зависимости из `requirements.txt`, затем из корня проекта запустите:

```powershell
python -m pytest -q
```

Тесты в `tests/test_api.py` проверяют health-check и справочники, создание/поиск заявки, валидацию и ссылки на отсутствующие записи, переходы статусов и мягкую архивацию. Для каждого теста используется отдельная временная SQLite-база.

## Docker: локальный запуск

```powershell
docker compose up --build -d
docker compose ps
Invoke-RestMethod http://localhost:8000/health
```

Откройте `http://localhost:8000/` и `http://localhost:8000/docs`. `.env` необязателен: Compose задаёт безопасные локальные значения по умолчанию; при необходимости можно переопределить переменные окружения. Данные хранятся в Docker volume `request_data`. `docker compose down` останавливает сервис; для полного удаления тестовой БД используйте осознанно `docker compose down -v`.

Образ запускает приложение от непривилегированного пользователя, использует slim-образ, устанавливает зависимости до копирования исходников и содержит Docker health check.

## Развёртывание на VPS с Docker Compose

1. Подготовьте Linux VPS с Docker Engine и Compose plugin; откройте выбранный HTTP/HTTPS порт.
2. Передайте репозиторий на сервер по SSH/Git и перейдите в каталог проекта.
3. Создайте `.env` из `.env.example`; для reverse proxy установите `PORT`, например `8000`. Не публикуйте секреты.
4. Выполните `docker compose up -d --build`.
5. Проверьте `curl http://127.0.0.1:8000/health`, `curl http://127.0.0.1:8000/requests` и внешний адрес после настройки HTTPS reverse proxy.
6. Зафиксируйте URL, дату и тип VPS в отчёте. Удалённое развёртывание этой копии ещё не выполнено: нет выбранного сервера и доступа к нему.

Перед публичным продакшеном добавьте аутентификацию и авторизацию по ролям, HTTPS, секреты, миграции, резервное копирование и ограничения запросов.

## Структура

```text

prototype/           UI, который вызывает REST API
scripts/             утилиты тестовых данных
docs/                ТЗ, архитектура, API-контракт, отчёты, запросы
docs/database/       ER-диаграмма и DDL-схема SQLite (ЛР № 5)

tests/               автоматические API-тесты (pytest)
```

## Ограничения артефактов

- Удалённый адрес деплоя не указан: выполнение удалённого деплоя требует VPS/облака и доступа владельца.
- В API нет аутентификации; идентификаторы автора/исполнителя демонстрационные.
- Docker и Compose должны быть установлены для контейнерного запуска.
- Удалённый деплой не выполнялся: необходимы VPS/облако, доступ и публичный адрес.
