## ЛР № 6. Разработка функционала

Реализован работающий слой приложения поверх SQLite: схемы и ограничения находятся в `app/db.py`, SQL-доступ — в `app/repository.py`, бизнес-правила — в `app/services.py`, входные данные — в `app/schemas.py`. Инициализация создаёт 4 пользователей, 4 категории, 4 статуса и 10 тестовых заявок.

| Требование | Реализация | Проверка |
|---|---|---|
| Создание | `POST /requests`, Pydantic и SQL CHECK | 201 и запись в SQLite |
| Список/карточка | `GET /requests`, `GET /requests/{id}` | JSON список / 404 |
| Редактирование | `PATCH /requests/{id}` | Проверка ссылок и полей |
| Статус | `PATCH /requests/{id}/status` | `ALLOWED_TRANSITIONS` в service |
| Исполнитель | `assignee_id` и выбор в UI | Внешний ключ users |
| Поиск | `q` по ID, теме, описанию | Query-параметр |
| Фильтры | status/category/priority | Совместимые query-параметры |
| Удаление | Soft archive через DELETE | Подтверждение в UI, 204 |
| Ошибки | 404/422/500, понятные `code/message` | Невалидный запрос и отсутствующий ID |

Автоматические проверки API находятся в `tests/test_api.py`. Набор покрывает health-check и справочники, создание/поиск/получение заявки, ошибки валидации и ссылок, разрешённый и запрещённый переходы статуса, а также архивирование. Запуск из корня проекта: `python -m pytest -q`. Каждый тест использует отдельную временную SQLite-базу, не затрагивая рабочие данные.

## ЛР № 7. REST API

API документируется автоматически через `/docs` и `/openapi.json`. Контракт и примеры находятся в `docs/API.md`, `docs/requests.http`, `docs/postman_collection.json`. Коллекция содержит более 10 запросов: health, список, поиск, два фильтра, карточка, три справочника, создание, изменение, статус, ошибка валидации и 404.

## ЛР № 8. Контейнеризация и деплой

Подготовлены `Dockerfile`, `.dockerignore`, `docker-compose.yml`, `.env.example` и `/health`. Контейнер использует Python 3.12 slim, непривилегированного пользователя, volume для SQLite и health-check. Инструкция локального запуска и повторного деплоя на VPS приведена в README.

Локальный контейнер успешно собран и запущен в Docker Desktop 11 октября 2026 г. По выводу `docker compose ps` контейнер `requestsystem-request-system-1` перешёл в состояние `healthy`, порт `8000` опубликован на localhost. Проверка `Invoke-RestMethod http://localhost:8000/health` вернула `status=ok`, `database=ok`. Скриншоты терминала сохранены в материалах пользователя.

Публичный удалённый деплой не выполнялся: доступ к VPS/облаку и публичный адрес не предоставлены. Поэтому URL, проверку извне и скриншоты удалённого запуска добавить нельзя; этот пункт остаётся незавершённым.
